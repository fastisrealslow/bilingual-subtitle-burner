# 恢复账户后的 FC 降本（2026-11-10）

目标保持为同等日更四条时费用降至基线10%；保留两个实验位、全部来源/字幕/封面/指纹门禁和长视频能力。

## 已取得的证据

- 账户恢复，10点档真实发布；重复 FC 统计时钟已关闭，CI 17/47分采样继续，原发布/补源时钟回读未改变。
- 在标准免费 GitHub runner 上仅上传不提交：bda2 的6,238,913字节传输65秒超时；QN相同文件3.339秒完成。另一台runner的90,999,152字节多分片文件17.4秒完成。两个测试没有创建稿件，也没有调用FC。
- 现有FC为0.5核/1GB，最小实例数0。账单读取仍为NotAuthorized，不能把计算量推算当作真实总账单。

## 实现

CI复用原出版函数和全局租约，优先走已测的QN线路；文件不重编码，上传前后复查实际SHA，使用原标题、简介、来源、分区及未选择声明参数，封面传原始已验收字节。提交请求只发送一次。提交超时/响应不明保留上传意图，走认证创作中心恢复，禁止换路重传。

只有确认没有提交（或接口明确返回不支持网页投稿）时，才能调用原FC精确交付通道补位；国内通道仍验证原文件、字幕和封面证据。成功回执记录实际传输后端和耗时，避免把CI上传当成FC消耗，或把文件上传当成已发布。

首次上线两个开关均关闭。真实到期稿件经CI发布、BVID/文件哈希/原时段/实验分组均一致、认证创作中心确认公开后，生成持久验收记录。切换时验证这条真实回执和相同版本代码，才将四个付费FC时钟换成一个21:55的境内补位时钟。正常发布仍由CI在北京时间10/14/16/21执行，另有半小时补查；日末补位最多填四个原始缺位，已完成时只读一次状态，不空等租约、不写空日志。

## 费用验收

按官方规则：计算量为资源规格乘执行时间；按函数活跃小时有最低消费，公网出流量单列CDT。公开仓库的标准GitHub托管runner计算免费。维持磁盘/内存规格，不减少成片数量、时长或质量。

11月6/7各有四条真实回执，最近100条异步执行在两天的CPU/内存、调用及小时最低消费估算分别约0.352/0.392元（未含同步调用、CDT及折扣）。健康主传路径不使用FC上传，日末一次空补位的小时最低消费约0.01元；稳态计算部分模型约基线3%，尚待真实发布后和账单比对。遇到主线路波动保留国内补位，并如实记录增加的消耗，不以停更换取预算达标。
