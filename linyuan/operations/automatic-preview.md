# 全自动样片验收

普通生产及直接运行 produce_cn.py 默认启用 `LINYUAN_AUTOMATIC_ONLY=true`：自动选段、真实模型观点复核、标题与封面生成、字幕排版和媒体门禁。历史按条修复仍为显式兼容入口，不能计作全自动验收。自动补库和质量重试不再继承历史人工选段、指定片号或单素材固定片数；仅保留来源、画幅、原始识别证据和去重历史。

此模式不读取历史素材的编辑选段、人工标题记录、人工 ASR 改字、预设取景框或逐素材话题表；也不接受传入的编辑标题或观点审核答案。人物识别参考图、素材原始时间等来源信息仍用于身份与出处核对，不提供文案或选段答案。自动模式有独立缓存身份，不能把历史人工修正的转写或文案当成新自动结果。

`linyuan-automatic-preview.yml` 从正式生产步骤生成，测试强制同步。它只有 GitHub 读取权限，去掉 Release、投稿、库存补位及发布入口，产物使用 `preview-` 前缀，工作流名称也与正式生产不同，避免触发正式库存完成事件。预览代码不加载阿里云凭据，也不调用 FC。

在 `codex/automatic-preview` 分支更新 `.github/linyuan-preview-request.json` 可启动预览。请求只接受源 URL、主讲人、场合、输出数量、版本备注，以及白名单内的模型与通用文案策略；禁止提供标题、时间段、放行开关。`max_outputs` 是通过全部检查后的输出上限，失败候选仍记入报告，不缩减质量检查。更换来源只改请求数据，不改业务规则。

查看实际 MP4、封面、完整字幕、生成与复核证据和批次失败记录后才能决定发布。预览成功不等于已发布，也不证明 30% 出片率或与对标账号质量齐平。已有线上定时发布是独立任务；预览隔离本身不暂停现有定时器。

修改正式工作流后运行 `python scripts/build_linyuan_automatic_preview.py`，再运行 `tests/test_linyuan_automatic_preview.py`。发布只应使用验收的同一文件与哈希，不允许临发布重新拟标题或替换内容。

## 自动生成实片对照页

`scripts/build_linyuan_preview_report.py` 从实际交付包自动读取标题、封面和视频，核对视频哈希后才显示播放器；缺少文件不会生成坏链接。用 `--preview-root` 指定下载的预览目录、`--baseline-metadata` 指定线上实片元数据、`--reference-root` 与 `--reference-index` 指定已取得的参考文件，`--output` 指定 HTML。比较页仅呈现证据，不向生产系统提供人工编辑答案，也不把单源预览当作固定 100 条成功率。
