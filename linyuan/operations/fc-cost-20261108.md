# FC 成本迁移验收记录（2026-11-08）

目标：总费用降到同等发布量基线的 10%；每天四条，第二/第四条实验位，以及全部质量、来源、查重、上传恢复与统计规则保留。

## 已核验

- 当前生产函数：0.5 vCPU、1024MB、10240MB 临时盘、7200 秒超时。
- 最小实例/预留实例均为零，不存在可直接取消的常驻保底实例。
- dispatch 小时触发器已关闭；publish 保留北京时间 10/14/16/21；统计 FC 每小时47分触发器仍启用，CI 另有每小时17分及生产完成回调。
- 2026-11-08 库存补发布返回提供商 403 `Current user is in debt`。部署/调用能否恢复要实测，不把欠费视为素材失败。
- 账单读取返回 `NotAuthorized`，尚无可验证的人民币支出基线，不能宣称已省90%。

## 本次实现与切换

CI 执行现有 publish_catchup/publish_handler，保留同一把全局流水线租约、真实时段配额、实验选择、来源限制、质量门禁和查重。只有通过全部门禁的单条文件、封面及字幕证据打成一个不可变 ZIP，绑定实际 MP4/包/清单哈希和持久上传意图后交给 FC。

FC 新通道只取这一包、重验实际文件及门禁并执行既有国内 biliup 命令。任务以固定 ID 跟踪，重试数零，额外用持久 CAS 防重。响应丢失、任务仍在执行和 CLI 超时保留原上传意图，走认证创作中心恢复；不会记为“执行完成”，不会换 ID 重传。老运行时的探测使用已熔断 slug，避免未知路由误发。

`fc_cost_policy.RUNNER_PUBLISH_ENABLED=False` 是待验收状态：原发布路径继续服务，新工作流只读预检。只有包内新模块、完整回归、实际库存预检、云端协议探测和一条正常到期稿件上传/真实回执通过后才切换。欠费未恢复时不得把此开关改成已上线。

CI 统计改为17/47分加原生产回调，保留固定24/72/168小时窗口与原实验截止日期。部署验证只关闭已证明归属的重复 FC 统计触发器，不改发布时段。

## 费用口径与后续验收

官方计费依据：

- https://help.aliyun.com/zh/functioncompute/billing-overview-of-fc
- https://help.aliyun.com/zh/functioncompute/pay-as-you-go-billing-methods
- https://docs.github.com/en/billing/concepts/product-billing/github-actions

FC 活跃 CPU/内存按配置乘运行时长计费，空跑、失败和等待同样可能付费。当前配置活跃计算量估算为 `0.65 CU/秒 + 0.0075 CU/调用`，这不包含函数活跃小时最低消费、CDT 流量、折扣或其他服务。减少调用次数不能直接等同于费用减少比例。标准 GitHub 托管 runner 在本公开仓库免费；不用付费大规格 runner。

待恢复后按同等日更四条比较至少七个完整自然日：FC 真实执行秒数、计算 CU、活跃小时、CDT 流量、失败/空跑数、BVID 实际回执、普通/实验数量、质检拒绝和素材补产。不以缩减发布、放宽门禁、遗漏统计、转移到别的收费项目或只比较单次调用实现达标。

提前批量定时投稿暂不直接改 `dtime`：这涉及平台最短预约窗口、预约/已公开回执区分、跨日配额和实验真实发布时间。应在上述迁移稳定后独立验证，避免把四条已上传错算成四条已发布。
