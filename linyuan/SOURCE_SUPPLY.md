# 林园素材供给与日常库存

用户约定：每天六条；每组至少五条真人动态、最多一条资料卡；成片至少 120 秒，以 2–3 分钟完整观点为主。CPU 离线 ASR，不调用识别 API、不用 Whisper large-v3。旧片和已隐藏短片不计入新六条。

## 2026-09-07 实际发现

09:00 北京时间发布触发器执行了，但可发布库存为零。任务在制数被标为 `pending_inventory`，掩盖了没有合格 MP4 的事实。另一个缺陷是 Release 取件未下载 v12 所需的真实 ASS，已经修复。实际读取的新片还有错误词语和残缺开场，`ly-0907-d04876`、`ly-0907-f95a57` 已暂停发布，前者正在用另一 CPU 离线模型实产复核；不能因工作流绿色或摘要通顺解除暂停。

初次检查的 2739 条记录包含 972 条对标参考、141 条会议公告，989 条视频线索中 924 条缺少时长。修复抓取后，02:29 UTC 的在线刷新已为 B 站/微博补回大量真实时长，符合 120–5400 秒时长范围的线索合计 303 条；这不是 303 条可用母片，更不是 303 条合格成片。还需取件、人物/取景/水印、完整论点和字幕质量检查。

历史对标目录中，972 条林园相关视频的时长中位数为 140 秒。园园把新书发布会等长活动分期，也围绕行业、公司和投资方法组织合集。学习其活动和主题索引，寻找原片；对标账号成片始终只作参考。旧活动必须保留真实时间语境，不包装成当日新发言。

## 程序负责的循环

1. 搜索保存真实发布日期和时长；发现时间单独由数据库记录。未知时长保持未知。
2. 根据参考目录活动词每天轮换原片检索；已知合集展开各页 cid，独立取件，绝不把 P2 偷换成 P1。无法核对上传者的页只保留线索。
3. 每个取源步骤最多 12 分钟；实际源质检先于离线识别和编码。坏片仍逐片隔离。
4. 母片转写缓存绑定原视频 SHA、模型和代码版本；仅复用原始转写，不复用剪辑审核批准。视频、模型或转写内容变化必须重新验证。
5. `source_supply.py` 核对实际 MP4 哈希、音视频完整解码、真实时长及 ASS 证据，保存到 `.automation/source_inventory.json`。记录母片、连续起止段、成片哈希和发布进度。转写质量还必须通过生产和发布门禁；已知异常批次不计库存。
6. FC 每半小时检查库存，目标十二条可按日更比例使用的储备；最多六个正在运行/排队的素材任务。用原子租约避免刷新和定时器重复派单。
7. 发布仍是北京时间 09、11、13、15、18、21 点，每天最多六条。读取库存中较早的 Artifact，不依赖最近三十次运行；取件有明确限时，失败等待重取，不能误判为素材差或盲目重传。

日常判断只看实际库存、已发布回执和各阶段失败原因，不把链接数、已派任务数、绿色工作流算成完成量。自动化代理只处理程序未能解决的异常，不再承担日常补源循环。

## 上线验收边界

十二条是储备目标，不是已经达到的事实。至少观察一次跨日储备及六个发布窗口，才可声称每天六条稳定。所有模型准确率、库存可支撑天数和发布时间承诺都须有实测证据。
