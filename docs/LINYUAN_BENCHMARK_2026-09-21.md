# 园园对标、16种试样与新模型实验

本轮没有把“园园风格”固定成一种模板。实际重新获取了 16 条参考的公开元数据、封面和视频流，检查 47 张真实抽帧；另以已有原始母片制作 **8 个竖版、8 个横版、4 个封面**试样。播放入口：`output/benchmark-20260921/index.html`，可筛选横竖版、播放原声试片、标记喜欢的样式和记录意见。

参考取样为：仓库 1038 条历史归档中按旧播放数选前 8 条，另取 6 条近期短片与 2 条特殊画面类型，再重新查询播放数据。它不是实时全站排行榜或随机样本。公开播放次数不是曝光点击率/完播率，也不能直接比较发布一年和发布一天的视频。

## 实际差别

| 维度 | 园园实际样本 | 我们现有问题 | 本轮实验方向 |
|---|---|---|---|
| 横竖版 | 历史高播放组 6 竖 2 横，近期所选 6 条全为横版画布；还有插画卡和活动拼图 | 自动流程倾向统一的真人要求与固定包装，音频卡关闭，部分来源没有合适出口 | 多种画面路线独立比较；人物不够大时保留横版语境，不强拉成近景 |
| 封面 | 真人组多用干净的人物近景；视频内部可以有大字观点条 | 容易把封面、投稿标题、片内标题当成同一个文字版式 | 4 种横版封面与 16 种片内布局分开比较 |
| 标题 | 本人的态度、具体对象、反差和口语推进，常用两三句完整话 | “谈某主题/配置策略/投资启示”像摘要，强原话被磨平；另一极端是模型加戏 | 每例试 6 种角度，允许鲜明语气，审核只拦新增事实/归属/限定错误，不以语气强为错 |
| 内容 | 高播放样本常有明确个人选择、经历或争议对象；近期论坛也保留主持人提问和多机位 | 一条片段混多个话题，标题只能覆盖开头；120 秒硬门槛限制完整短观点 | 先确定独立看点和上下文边界，再写标题；短观点先单独实验 |
| 画面验收 | 参考里有主持人、反应镜头、资料插图，不是每帧都为林园近景 | 人物连续性规则与这种形式不完全相容，清理失败又没有另一合格路线 | 分开核验身份、源清晰度和最终布局，不简单降低人脸阈值 |

参考数据与逐条观察见 [references.json](../linyuan/simulations/benchmark-20260921/references.json)。本轮只做实际抽帧与标题/字幕可见信息分析，未全片听看，因此不声称已完整验证其声音、剪辑节奏或每句原话。

## 已做的模拟

16 条试样均为同一个 **12.2 秒原声片段**，用于比较版式，不是 16 条可投稿成片。来源 BV1h6QWYsEz5，SHA256 `4c711fb59cdec677f1eacc7f6603f27d5b4231f6ab841fc4d421a0079b5d2846`，起点 2489.48 秒。人物裁切坐标仅用于这段人工检查过的素材，不写成通用规则；P07 使用基于项目身份参考生成的原创插画，并明确标注“AI人物插画 · 原声片段”；[提示词与来源记录](../linyuan/simulations/benchmark-20260921/illustration-prompt.md)保留生成方式和文件指纹。字幕合并了原断行、省略少量口头填充，保留观点，不把这组试样作为 ASR 或时序精度验收。

- 竖版：黑底观点条、原话两句、暖白访谈、放大真人、两人语境、单句留白、AI人物音频卡、人物/现场拼图。
- 横版：近景原画、深色字幕带、浅色字幕带、顶部原话、左右观点与真人、两人语境、现场配短句、双行开场。
- 封面：干净真人、近景加短句、留白分栏、底部观点；均带 160×90 对照。

这些试样用于选方向，未进行点击率实验，也未使用竞品图片作为我们的视频画面。对照视频中，AI 短片的公开流仅取得前 30.1 秒、活动拼图仅取得前 600.1 秒；其余可见范围见每条 inspection 记录，不能把局部抽帧写成看完整片。

## 内容比换模板更优先

上一轮 267.7 秒样片开头约 12 秒谈医药经营，随后换到安慰自己/被拖欠房租、规模扩张、车厂调研。继续用“医药股”覆盖整条，题目与内容主线就不一致。可拆的编辑草案：

| 原片区间 | 内容 | 标题草案 |
|---|---|---|
| 2489.48–2501.64 | 医药公司也有经营不好的 | 林园：医药股也有经营不好的，别乱买 |
| 2584.36–2614.04 | 租客半年没交租，先让其腾房 | 林园：半年没付我房租，我先让他把房子腾回来 |
| 2696.76–2735.16 | 回应去车厂调研的说法 | 林园：我就跟朋友去车厂转一圈，没太多精力放上面 |

这些是原字幕支持的编辑建议，仍需听音确认，并不自动放宽生产 120 秒规则。更吸引人的方向是个人经历、明确选择、原有矛盾和有力度的语言，而不是统一添加“震惊”“内幕”或收益判断。

## 新模型：实际启动三组配置

当前生产默认 qwen3:8b，并在代码中写死 `think=False`。较新的 [Qwen3.5 9B](https://huggingface.co/Qwen/Qwen3.5-9B)支持思考/非思考；[Ollama 的 9B 包](https://ollama.com/library/qwen3.5:9b)为 Q4_K_M，约 6.6GB，模型文件大小不是最终内存峰值。使用 [Ollama API 的 think 开关](https://docs.ollama.com/capabilities/thinking)，不能仅在提示词里加“想一想”。

[独立 Actions 实验](https://github.com/fastisrealslow/bilingual-subtitle-burner/actions/runs/35545423737)已启动，4 组真实字幕 × 3 配置，每组生成 6 个角度，最多 72 个候选：

1. qwen3:8b，不思考。
2. qwen3.5:9b，不思考。
3. qwen3.5:9b，开启思考。

统一原文、提示词、上下文 16K、temperature 0.7、随机种子，9B 使用其 presence penalty 1.5；思考组有更大输出预算。因此这是实际配置对比，不是只改变一个变量的模型能力测量。每项分生成、独立审核两个请求；保存精确引用、代码/原文指纹、token/耗时、截断与失败，思考组检查确实返回 thinking 字段。只采用最终 JSON，不把思考文本当标题。连续引用与逐项审核完整性另由程序检查。

标题 workflow 与下载、ASR、渲染分离，失败不必重跑整条出片。它不是一台常驻模型服务器：每个 job 是临时 CPU 环境，模型权重缓存，任务结束后释放。默认最多同时 6 个 job；未调用付费 API、未自动发布或替换生产模型。

初批结果说明“更新更大”不必然更适合：9B 非思考输出曾加入“为了躲回撤”“更懂如何逼债”等原文没有的意图。8B 也会把主持人的话混进来。这批结果还在收集，不应仅按模型自评数量决定升级。最终选择同时看自然度、原话力度、事实准确性、耗时和失败率。

建议生产逐步采用“源/ASR 证据固定 → 独立标题实验与复核 → 只为选中方案渲染 → 实片验收”的分段方式。当前实验产物刻意不生成可复用的生产审核证明，防止把实验成功当成发布许可。

## 最近 Actions 的具体错误与已修代码

[逐项记录](../linyuan/simulations/benchmark-20260921/actions-review.json)区分母片失败、调度依赖和结果验收：

- [35542300592](https://github.com/fastisrealslow/bilingual-subtitle-burner/actions/runs/35542300592)：报“连续 2.03 秒无脸”。实看失败帧是资料插图；此前 1018 帧里 954 帧虽然身份匹配，却小于 96 像素门槛，合格目标帧为 0、最大 95.85 像素。因此不是只调大两秒就能解决，应重新选原片/布局，不能把小脸强拉大。
- [35542292753](https://github.com/fastisrealslow/bilingual-subtitle-burner/actions/runs/35542292753)：身份 0/18 匹配。实看是带旧字幕、标识和黑边的远景多人论坛；整帧短边 1078 不代表人脸清楚。不据此直接断言人物不对，也不降低身份阈值，应优先寻找同场近景源。
- [35531042226](https://github.com/fastisrealslow/bilingual-subtitle-burner/actions/runs/35531042226)：原画清理不能通过，自动发布禁用音频卡，没有合格回退。
- [库存](https://github.com/fastisrealslow/bilingual-subtitle-burner/actions/runs/35542769755)与[调度](https://github.com/fastisrealslow/bilingual-subtitle-burner/actions/runs/35542300581)：阿里云 `403 / Current user is in debt`，属于账户依赖阻塞，不是素材质量问题。
- 每日四条验收失败是产量/回执的结果性告警，不能再算一次素材失败。

**代码侧已修：**队首需要大陆中转的候选不再直接终止整个 GitHub 候选循环。先处理后续可直达的 B站/微博来源；只有本轮仍有缺口才请求中转。大陆候选不被误判拒绝、不改写、不绕过原有配额/去重。账户欠费单独记录为外部依赖，保留已成功调度数且不更改定时器；没有替用户充值或修改云账户。

## 复现与验证

```bash
# 固定参考组刷新；仅抓公开参考，不写入生产素材库
.venv311/bin/python scripts/collect_linyuan_benchmark.py
# 已有母片 + 本地 ffmpeg（--ffmpeg 可指定路径）
.venv311/bin/python scripts/preview_linyuan_formats.py
.venv311/bin/python scripts/build_linyuan_benchmark_page.py
open output/benchmark-20260921/index.html
bash scripts/check_linyuan_local.sh
```

本机本轮通过 `imageio-ffmpeg` 安装了可运行的 FFmpeg 7.1，作为显式预览工具使用；没有把它冒充全系统 ffmpeg/ffprobe 环境。16 个试片均完成视频和音频全程解码检查，尺寸、时长与文件指纹另存本地 `variants/validation.json`。本地扩展回归 272 passed、1 skipped，跳过项仍依赖 PATH 中的 ffmpeg；新调度测试验证了大陆队首、直达候选、剩余配额和欠费回执。

所有代码在草稿 PR #40，实验与成片模板仍未部署为默认生产设置。完整视频、参考图和模型原始调用位于 Git 忽略的本地 output/ 或 Actions artifacts，仓库只存脚本、精简结果与观察记录。
